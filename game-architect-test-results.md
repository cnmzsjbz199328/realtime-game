CORE LOGIC\n\n### 2.1 Game State Management\n\nThe `state` object holds all dynamic game information. `initGame(state, w, h)` is called to set up a new game, including level configuration, resetting resources, and clearing entities. `update(state, input, dt)` is the main game loop, responsible for advancing all game elements. `draw(state, ctx, w, h)` renders the current game state.\n\n### 2.2 Wave Management\n\n- `state.wave`: Increments after each wave.\n- `state.waveTimer`: A countdown to the start of the next wave. When `state.waveTimer <= 0`, a new wave is spawned.\n- **Wave Spawning**:\n    - When `state.waveTimer <= 0` and `state.gameState === STATE_ENUM.PLAYING`:\n        - Increment `state.wave`.\n        - Reset `state.waveTimer` to `CONFIG.WAVE_DELAY`.\n        - Calculate number and types of enemies for the wave (increasing difficulty with `state.wave`).\n        - For each enemy to spawn:\n            - Get the starting waypoint position from `state.levelConfig.waypoints[0]`.\n            - Create a new `Enemy` object of the appropriate type.\n            - Assign `enemy.path = state.levelConfig.waypoints`.\n            - Add the enemy to `state.enemies`.\n        - Add `CONFIG.GOLD_PER_WAVE` to `state.gold`.\n\n### 2.3 Enemy Pathing and Core Damage\n\n- **Enemy Movement**: Each `Enemy` object has a `path` (an array of `Vector` points) and a `currentWaypointIndex`.\n- In `Enemy.update()`:\n    - If the enemy has a `targetTower` and is attacking, move towards the tower.\n    - Otherwise, calculate the direction to `this.path[this.currentWaypointIndex]`.\n    - Move the enemy towards the waypoint using `this.speed * dt`.\n    - If the enemy is close to the waypoint (`distance < 5`), increment `this.currentWaypointIndex`.\n    - If `this.currentWaypointIndex` exceeds the path length, the enemy has reached the core:\n        - Subtract damage from `state.core.health`.\n        - Mark the enemy as inactive (`this.active = false`).\n        - Add visual feedback (particles).\n\n### 2.4 Tower Placement and Building\n\n- **Placement Mode**: When a tower button is clicked (via `input.mouse.isDown` on specific UI elements):\n    - Set `state.placementMode = true`.\n    - Set `state.placementGhost.type` to the selected tower type.\n    - Set `state.placementGhost.cost`.\n    - `state.selectedTowerIndex = -1` (deselect any existing tower).\n- **Placement Ghost**: While `state.placementMode` is true:\n    - In `update(state, input, dt)`:\n        - Update `state.placementGhost.x = input.x` and `state.placementGhost.y = input.y`.\n    - In `draw(state, ctx, w, h)`:\n        - If `state.placementMode`:\n            
- Draw the tower ghost at `state.placementGhost.x, state.placementGhost.y`.\n            - Check if the placement is valid (within grid, not overlapping other towers, sufficient gold).\n            - Display placement cost and validity indicator (e.g., red if invalid).\n- **Confirming Placement**:\n    - If `input.mouse.isDown` is true while `state.placementMode` is active:\n        - Check for valid placement:\n            - **Grid Alignment**: `placementX = Math.floor(input.x / CONFIG.GRID_SIZE) * CONFIG.GRID_SIZE + CONFIG.GRID_SIZE / 2;` and `placementY = Math.floor(input.y / CONFIG.GRID_SIZE) * CONFIG.GRID_SIZE + CONFIG.GRID_SIZE / 2;` (snap to grid).\n            - **Sufficient Gold**: `state.gold >= state.placementGhost.cost`.\n            - **No Tower Overlap**: Check `Vector.distance` between ghost position and existing tower positions against tower radii.\n            - **Within Bounds**: Ensure placement is within canvas.\n        - If placement is valid:\n            - Deduct cost from `state.gold`.\n            - Create a new `Tower` object at the snapped grid position.\n            - Add the tower to `state.towers`.\n            - Set `state.placementMode = false`, `state.placementGhost.type = null`.\n        - If placement is invalid, cancel placement mode (`state.placementMode = false`).\n\n### 2.5 Tower Combat and Targeting\n\n- **Targeting**: In `Tower.update()`:\n    - If `cooldownTimer <= 0`:\n        - Call `findTarget(state.enemies)`: Iterate through `state.enemies` and find the closest active enemy within `this.range`.\n        - If a target is found, `this.target = targetEnemy`.\n- **Firing**: In `Tower.fire(state)`:\n    - If `this.target` is valid and active:\n        - Create a new `Projectile` object with parameters based on tower type (damage, speed, color, type).\n        - Add the projectile to `state.projectiles`.\n        - Reset `this.cooldownTimer = this.shootCooldown`.\n        - Add particle effects for weapon firing.\n- **Projectile Logic**: In `Projectile.update()`:\n    - Move the projectile towards its `targetX, targetY` using its `velocity`.\n    - If the projectile reaches its target distance or slightly beyond:\n        - Call `impact(state)`.\n        - Mark projectile as inactive.\n- **Impact Logic**: In `Projectile.impact(state)`:\n    - **Laser**: Direct damage to a single enemy (closest within impact radius). Add particles.\n    - **Mortar**: Area-of-effect damage. Iterate through `state.enemies` and apply damage if within `this.aoeRadius`. Add explosion particles.\n    - **Freezer**: Apply a slow effect to the hit enemy (add a `slowedUntil` timestamp and reduce `enemy.speed`). Add particles.\n    - When an enemy is killed (`health <= 0`):\n        - Mark enemy as inactive (`enemy.active = false`).\n        - Add `CONFIG.GOLD_PER_KILL` to `state.gold`.\n        - Generate particles.\n\n### 2.6 Breacher and Boss Enemy Behaviors\n\n- **Breacher**: In `Enemy.update()`:\n    - If `behavior === \"breach\"` and `attackCooldown <= 0`:\n        - `findAndAttackTower()`: Find the closest active tower.\n        - If a tower is targeted:\n            - Move towards the tower.\n         
   - If within range of the tower, deal percentage-based damage to the tower's `health`.\n            - If tower health drops to 0 or less, mark tower as inactive.\n            - Mark the Breacher enemy as inactive (consumed).\n            - Reset `attackCooldown`.\n- **Boss**: In `Enemy.update()`:\n    - Similar to Breacher but with higher damage and potentially different targeting logic (e.g., target towers closer to the core).\n    - Deals fixed `CONFIG.BOSS_ATTACK_DAMAGE` to towers.\n\n### 2.7 Tower Repair and Health\n\n- **Tower Health**: Towers have `health` and `maxHealth`.\n- **Damage**: Enemies (Breachers/Bosses) and possibly environmental hazards can damage towers.\n- **Repair UI**:\n    - When a tower is clicked (and not in placement mode):\n        - Set `state.selectedTowerIndex` to the clicked tower's index.\n        - Populate `state.ui.selectedTowerUI` with tower details (health, repair cost).\n- **Repair Action**:\n    - If the player clicks a \"Repair\" button in the UI:\n        - Calculate repair cost: `cost = (tower.maxHealth - tower.health) * CONFIG.TOWER_REPAIR_COST_PER_HEALTH`.\n        - If `state.gold >= cost`:\n          
  - Deduct cost from `state.gold`.\n            - Fully restore `tower.health`.\n            - Add visual feedback.\n- **Tower Destruction**: If `tower.health <= 0`, set `tower.active = false`.\n\n### 2.8 UI and Menu System\n\n- **Menu Screen (`STATE_ENUM.MENU`)**: Displays play/options buttons.\n- **Playing Screen (`STATE_ENUM.PLAYING`)**: Displays gold, wave number, core health, tower placement buttons, and selected tower UI.\n- **Game Over Screen (`STATE_ENUM.GAME_OVER`)**: Displays score (waves survived, gold) and retry/menu options. Triggered when `state.core.health <= 0`.\n\n### 2.9 Particle Effects\n\n- **Particle Generation**: Created when projectiles hit, enemies die, weapons fire, etc.\n- **Particle Properties**: Each `Particle` has properties like `lifespan`, `speedMultiplier`, `type` (e.g., 'explosion', 'trail'), and `angle`.\n- **Particle Update**: Particles move according to their velocity, shrink over time, and fade out.
