# 游戏设计指南：迷宫游戏

## 核心玩法循环
1. 玩家在迷宫中寻找出口
2. 避开或击败敌人
3. 收集钥匙、道具
4. 到达出口进入下一关

## 典型游戏元素

### 迷宫结构
- **墙壁**: 不可穿越的障碍
- **通道**: 可移动区域
- **出口**: 关卡目标
- **房间**: 开阔区域，可能有敌人或宝箱

### 玩家系统
- **移动**: WASD，网格或自由移动
- **碰撞**: 与墙壁碰撞时停止
- **视野**: 可选迷雾效果，只显示周围区域
- **能力**: 可选冲刺、传送

### 敌人系统
- **巡逻型**: 固定路线移动
- **追击型**: 检测到玩家后追赶
- **射击型**: 远程攻击
- **行为**: 简单AI或寻路算法

### 道具系统
- **钥匙**: 开启特定门
- **生命**: 恢复血量
- **武器**: 攻击敌人
- **地图**: 显示全局迷宫

### 关卡设计
- **难度1**: 简单迷宫，无敌人
- **难度2**: 复杂迷宫，少量敌人
- **难度3**: 大型迷宫，多种敌人，需要钥匙

## 视觉风格建议
- **背景**: 深色（#000000, #0a0a0c）
- **墙壁**: 霓虹蓝/紫边框（#3333ff, #ff00ff）
- **玩家**: 青色发光（#00ffff）
- **敌人**: 红色/黄色（#ff0000, #ffff00）
- **出口**: 绿色发光（#00ff00）
- **迷雾**: 半透明黑色渐变

## System Prompt
你正在开发一个迷宫游戏。参考上述设计指南，自由实现游戏逻辑。

**关键要求**：
- **迷宫生成算法**: 严禁使用简单的随机噪点 (Random Noise)。必须使用 DFS (深度优先搜索)、Prim 算法或递归回溯算法生成确保连通的迷宫。保证起点到终点至少有一条路径。
- 实现迷宫数据结构（二维数组或实体列表）
- 玩家与墙壁的碰撞检测
- 敌人AI（巡逻或追击）
- 出口检测和关卡切换
- 使用 `entity.tag` 区分类型（player, wall, enemy, goal）
- 所有实体继承自 `GameObject`
